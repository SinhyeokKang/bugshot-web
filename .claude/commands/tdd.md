테스트 코드를 **먼저** 짜는 단계 전용 스킬. 구현은 다음 단계에서 사용자 판단으로. 이 스킬은 **테스트 파일만** 만들고, fail 확인하고, 끝낸다.

## 사용

- `/tdd` — 직전 컨텍스트에서 모드 자동 판단.
- `/tdd interface <대상 설명>` — **A 모드**: 신규 함수·헬퍼 시그니처를 테스트로 결정.
- `/tdd regression <버그 설명>` — **B 모드**: 발견된 버그·엣지케이스를 재현하는 테스트.

## TDD 판단 기준 (정적 랜딩 사이트)

### ✅ TDD 강제
- **순수 함수 헬퍼**: `src/lib/*` (유틸, 포매터, 파서 등)
- **정규식·매핑 테이블**: URL 파싱, 디바이스 감지 등
- **재현되는 버그**: 입력으로 깨지는 게 확정된 케이스

### ❌ TDD 스킵 OK
- **React 컴포넌트 동작·레이아웃**: 실 브라우저 검증이 더 정확
- **정적 콘텐츠 렌더링**: 빌드 + 브라우저 확인으로 충분
- **SEO 메타 태그**: 빌드 후 `out/index.html` 검사가 더 정확

스킵 결정 시 **이유를 한 줄로 보고**하고 종료.

## 절차

### 1. 모드·범위 결정
- 인자에서 모드 추출 (`interface` / `regression` / 자동).
- 분류표(위 ✅/❌)와 대조. 강제/스킵을 먼저 결론.
- 스킵이면 이유 보고 후 종료.

### 2. 테스트 파일 위치 결정
- 컨벤션: 대상과 같은 디렉터리의 `__tests__/*.test.ts`.
- 기존 테스트 파일에 케이스 추가가 자연스러우면 신규 생성 금지.

### 3. 테스트 작성
- **Vitest** 사용.
- AAA: Arrange / Act / Assert. 한 `it`에 한 가지만.
- 케이스 갯수: 정상 1~2 + 엣지 2~4 + 에러 1~2가 표준.

### 4. fail 확인
- `pnpm test --run <테스트파일경로>`.
- red 확인됨 → 보고. 예상치 않게 pass → 재검토.

### 5. 종료
- 변경 파일 목록과 fail 메시지 핵심만 보고.
- **구현·픽스 안 함. 커밋 안 함. 빌드 안 함.**

## 금지 사항
- **구현 코드 작성 금지**.
- **기존 테스트 임의 수정 금지**.
- **모킹 남발 금지**.
- **빌드·typecheck·커밋 안 함**.
